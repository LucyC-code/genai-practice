# CampusCue demo script — approximately 2 minutes 45 seconds

Use only synthetic announcement text. Start both existing workflows and verify the preview opens. The script assumes a synthetic demonstration, not a real campus invitation. No video has been recorded or uploaded.

## 0:00–0:25 — Intended user and problem

“CampusCue is for Notre Dame students trying to find relevant campus events across scattered announcements. It turns pasted text into structured cards, but keeps students in control of what gets published.”

Show Discover on a narrow/mobile-sized viewport. Select Career, Networking, Social and Faith & Spirituality, then Graduate. Leave the time window blank.

## 0:25–0:55 — A meaningful discovery revision

“Feedback showed that recurring dorm Masses could dominate the feed. These occurrences are now grouped after filtering, not deleted. The card shows the next matching time and the number of matches.”

Expand **Campus Masses**, show dates, locations and original sources, then collapse. Counts depend on the current date. If no future occurrences remain in the old research snapshot, select a known historical Mass date rather than implying the source data is current.

“Under the same controlled October 3 research clock, our evaluation reduced 1,087 matching occurrences to 37 cards while preserving 1,051 matching Mass times.”

## 0:55–1:45 — Announcement to reviewed event

Go to Submit. Show the permission/privacy notice. Set original post time to **October 30, 2026, 9:30 PM campus time**.

Paste: **Free boba and board games tomorrow at 7pm in Duncan 210.**

“The app already uses live AI, not prewritten responses. It suggests editable fields; deterministic campus-date rules interpret tomorrow as October 31.”

Show date October 31, start 7 PM, Duncan 210, absolute summary, source text, reference note and unknown host/end. Rename the title to **SYNTHETIC DEMO — Boba board games** and add a Synthetic tag.

“I must check these details against the source. Unknown facts stay unconfirmed. Publishing requires a title, date, start time and my explicit review. Editing resets that confirmation.”

Check the review box and publish **only if you intend to create this labeled demonstration record**. Otherwise explain that Publish remains the explicit final step and use the recorded browser evaluation as publication evidence. If publishing, choose October 31 in Discover to find this historical-date sample; it is intentionally outside the default upcoming feed.

## 1:45–2:15 — Risk safeguard and time revision

Clear input/drafts. Paste: **Startup Pitch Night this Thursday in DeBartolo. Link in bio to RSVP.**

“This has no time, room, host or actual RSVP link. The missing start time blocks publication. I can edit or discard it, not silently add a misleading card.”

If extraction latency would exceed the recording time, prepare this draft before recording or use the evaluation screenshot, clearly identifying it as a test result.

Briefly show a 10 PM–2 AM window. “This now crosses midnight. Known intervals must fit fully; start-only events show an unknown-end warning, and unknown starts are excluded. No matches means an honest empty state.”

## 2:15–2:45 — Evidence, limitation and next priority

“Thirty-one deterministic tests passed, and live/API plus browser results are documented separately. AI wording varied, and one challenge’s model date required deterministic correction. Human review still matters.”

“This is a prototype with researched event snapshots, not a continuously verified calendar. Raw input is not saved by this app, but ordinary extraction sends text to an external service whose retention we do not control. A next priority is source-backed grouping for other recurring clubs.”

End on README’s evaluation/disclosure links. After recording: upload to Google Drive, grant instructor access, replace the Demo Video placeholder, and submit the repository link plus the video file in Canvas.
